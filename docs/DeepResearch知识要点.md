>
> **降级条 30 秒口述版（每格一句话，10/22 加；不占主打位但作开场/点缀时照此说）**：
> - **001（开场用）**：问题——启动定编排、搜索、LLM 接入三件事；选型——LangGraph 管控制流、百炼 MCP 管搜索、OpenAI 兼容管模型可插拔；放弃——AgentExecutor 表达不了扇出+循环、CrewAI/AutoGen 当时不稳、SerpAPI 中文差、自建有运维；取舍——**用学习曲线和解析复杂度，换控制流自由＋零搜索运维＋改环境变量切模型**。
> - **002（证据点缀用）**：问题——宽泛需求报告跑偏，5 并发触发 429；选型——计划后停下等确认，搜索前过令牌桶；放弃——不做 HITL＝返工浪费配额，只重试不限流＝不可靠；取舍——**多等 10-30 秒、排队 0.4 秒，换相关性提升和 429 从 30% 压到 5% 以下**（口述只带 30%→5% 一组数，其余归追问层）。

- **001 技术栈**：定编排/搜索/LLM 三件事 → LangGraph＋百炼 MCP＋OpenAI 兼容协议；弃 AgentExecutor（不支持 Fan-out+条件循环）、CrewAI/AutoGen（版本不稳）、SerpAPI（中文差需配额）；取舍＝学习曲线+解析成本 换 控制流/零运维/模型可插拔
- **002 HITL+速率限制**：需求宽泛致报告不符预期 + 搜索频繁限流 → 计划确认环节 + 令牌桶；取舍＝+10-30s 等待换报告相关性（原文无满意度百分比，勿编），429 错误率约 30%→5% 以下（代价 5 条排队约 +0.4s）
- **003 Sub-Graph 多 Agent**（⭐主打）：单体图过长难测难维护、每次跑全图质量不可控 → 三子图独立编译、主图条件边串联；取舍＝换来子图独立调试与质量可控（⏳措辞待 Day2 graph 精读对原文确认），付出＝OverallState 字段依赖（8→23）需多处同步
- **004 Milvus+Redis**：语义检索历史事实 + 跨请求缓存 → Milvus 存事实、Redis 只做搜索缓存；取舍＝+两套基础设施与 LLM 调用，换搜索 API 调用量降、缓存命中、部署简单
- **005 LLM-as-Judge**（⭐主打）：传统测试无法度量幻觉/覆盖/引用质量 → 独立评估框架，端到端（5 维×1-5 分）+组件级（7 维）；取舍＝+LLM 调用，换可量化追踪、可历史对比、组件级定位
- **006 异常分类与重试**：无效重试+重试分散+异常信息丢 → 三层异常分类（可恢复/不可恢复）统一重试；取舍＝理解复杂度↑ 换 重试时间↓与排查易
- **007 异步化+流式**：同步占线程池、报告等待无进展感 → 全链路异步 + LLM 流式；取舍＝线程占用↓体验↑，代价＝测试工作量↑
- **008 Redis Streams 任务队列**：异步/流式易连接超时 + 需等用户确认，HTTP 无法表达 → Streams 任务队列与事件流；取舍＝+Redis 组件与单点风险，换断线重连

### 2.2 决策链地图（后段 009-012）

- **009 KB 生命周期**：事实随时间老化仍影响当前查询 → 四档渐进增强 off→inform→freshness（默认）→lifecycle；阈值 7/30/180 天、decay = max(0.3, 1−age/(2·max_age))；取舍＝实时性 换 TTL 偏差+测试量；放弃项 ⏳（扫卡不回头补）
- **010 JSON 鲁棒解析**：LLM 偶发不规范 JSON 断流水线 → 多层提取从宽松到严格逐级尝试；取舍＝解析成功率↑，风险＝掩盖真错；放弃项表述 ⏳
- **011 分层测试**：测试散落依赖真实 API → Unit/Integration/E2E 三层 + mock（Unit ~120 <5s／Integ ~90 <15s／E2E ~4 5-10min；214 测试 <20s，来源 ADR-011）；Mock 边界＝LLM/MCP/Milvus/Embedding 四类，**Redis 用真实实例不 mock**；取舍＝效率+覆盖 换 mock 同步维护、Integration 不验 LLM 质量；放弃项 ⏳
- **012 交叉编码器精排**（⭐主打，与 004 成链）：KB 语义相近≠最相关、Web 结果含噪声 → DashScope `gte-rerank` KB/Web 双独立开关；弃本地模型（已兼容、统一认证）与 LLM 逐条打分（N 次调用，慢 10-50 倍、成本高一个数量级，原文 §理由）；召回扩展 `limit = max(top_k*3, 20)`、`rerank()` 永不抛异常只降级；取舍＝更贴事实+零部署成本，代价＝+1 次 API、精排后 top_k 减少丢边缘信息

## 3. 架构设计：多 Agent 拆分与协作（主挂 ADR-003）

- 三个子图职责：主图只管 Plan 确认与调度 / ResearchAgent 封装「搜索→评估→补搜」循环 / WriterAgent 封装「提纲→草稿→Critic→修订」循环
- 协作方式：子图各自独立编译，主图条件边串联；状态经 `OverallState` 传递（字段 8 → 23，来源 ADR-003）
- Debate Loop 退出条件：`ready_for_polish=True` 或 `revision_count >= 3`；Critic 评分 <6 自动修订（来源 ADR-003）
- README 自述四节点：generate_search / web_search / critique / final_answer

## 4. 知识库：选型 / 设计 / 验证（主挂 ADR-004 + 009 + 012）

- 选型：Milvus 自托管（数据不出域、Dynamic Field 免 migration、IVF_FLAT 适配 10 万级事实量级）；**Redis 只做搜索缓存，不做向量检索**（纯 Redis 不支持向量检索，来源 ADR-004）
- 缓存降级：Redis 不可用 → 进程内内存缓存，业务无感（来源 ADR-004）
- 生命周期四档：off / inform / freshness（默认）/ lifecycle；敏感度阈值 7 / 30 / 180 天；衰减公式 `decay = max(0.3, 1 - age/(2·max_age))`（来源 ADR-009）
- 精排：DashScope `gte-rerank`，KB 与 Web 双独立开关，召回扩展 `limit = max(top_k*3, 20)`，`rerank()` 永不抛异常只降级（来源 ADR-012）
- 验证：见第 5 节（LLM-as-Judge 组件级 + 分层测试）

## 5. 质量与上线标准（主挂 ADR-005 + 011）
